# 文字数カウンター SEOクラスタ方針

本書は、文字数カウント（`https://count.it-araiguma.com/`）の集客方針（#9）を確定させ、目標値・クラスタ構成・ページ追加基準・判定ゲート・計測手順を定める正本です。
用途別ページ個別の調査と優先順位は [`feature-pages-plan.md`](feature-pages-plan.md)、URL方式は [`routing-architecture.md`](routing-architecture.md)、Search Console の登録状態は [`search-console-status.md`](search-console-status.md) を参照してください。

---

## 1. 目的と基本方針

- 自作開発物で月1万円の自由資金を得る候補の1つとして運用する。
- 単体ツール（トップページ）で「文字数カウント」のビッグキーワードを取りに行くのではなく、**用途別ページの束（クラスタ）で検索面を取る**。
- 各ページはツール（すぐ使える計算機能）と解説（検索意図を満たす本文）を併せ持つ。

### 1.1. 目標値の根拠

| 項目 | 値 | 出典 |
| :--- | :--- | :--- |
| 広告単価 | 1,000PVあたり 107〜180円 | 本人ブログの実績値 |
| 月1万円に必要なPV | 月 5.6万〜9.3万PV | 10,000円 ÷ 上記単価 |
| 到達条件 | 主要KWで3位級 ＋ 用途別クラスタが揃っている状態 | #9 |

同ドメインの `display.it-araiguma.com`（画面サイズチェッカー）が同名キーワードで7位を取っており、このドメインでもツールSEOが成立し得る。

## 3. クラスタ構成

```
トップ（/）……汎用文字数カウント＝ハブ
 ├─ /genko        原稿用紙換算カウンター（第1弾・公開済み）
 ├─ /report       レポート・小論文文字数チェッカー（第2弾）
 ├─ /sns          X（旧Twitter）文字数・ポスト分割（第3弾）
 ├─ /lines        行数カウント・テキスト整理（第4弾）
 └─ /entry-sheet  エントリーシート・志望動機文字数（第5弾）
外部導線：ブログ it-araiguma.com の関連記事 → 各ページ（#14）
```

- 順序は [`feature-pages-plan.md`](feature-pages-plan.md) §3 の優先順位に従う。
- **内部リンク**:
  - ハブ → 全ページ：トップから各用途別ページへリンクする。
  - 各ページ → ハブ：パンくずかヘッダーでトップへ戻れるようにする。
  - 関連ページ同士：`/report` と `/entry-sheet`、`/genko` と `/report` のように、用途が近いページを相互にリンクする。
- 各ページは固有の `title`・`description`・`canonical`・`<h1>` を持ち（`src/utils/seo.ts`）、`public/sitemap.xml` に登録する。

## 4. ページ追加の基準（量産の禁止）

新しい用途別ページは、次をすべて満たす場合だけ追加する。

1. **検索意図が既存ページと重ならない**：同じ意図の言い換えページ（例：「文字数 数える」専用ページ）は作らない。
2. **固有の機能がある**：汎用カウンターの見た目替えではなく、その用途でしか要らない計算・判定を持つ（例：原稿用紙の改行考慮換算、レポートの割合判定）。
3. **解説本文がある**：その用途のルール・注意点を同じページで説明し、検索意図を満たす。
4. **計測できる**：公開と同時にサイトマップへ登録し、GA4 でページ別PVを確認できる。

前のページが未インデックスのまま次を量産しない。新ページはインデックスを確認してから次へ進む（目安）。

## 5. やらないこと

- 単体トップページだけで順位を狙う施策
- 量産だけを目的にしたページ追加（§4 を満たさないページ）
- 推測値を実績として記録すること（§6.2）

## 6. 判定ゲートと計測

### 6.1. 判定ゲート

起点は基盤を復旧した 2026-11-15 とする。

| ゲート | 判定日 | 確認する指標 | 継続の目安 | 目安に届かない場合 |
| :--- | :--- | :--- | :--- | :--- |
| 4週 | 2026-12-13 | インデックス済みページ数、Search Console の表示回数 | 公開済みページ（`/`・`/genko`）がインデックスされ、表示回数が0でない | クロール・レンダリング・サイトマップを調べて原因を直す（撤退判断はしない） |
| 12週 | 2027-02-07 | 掲載順位（用途別KW・主要KW）、Organic Search のPV | 用途別KWのいずれかで20位以内、Organic Search のPVが増加傾向 | ページの中身（機能・解説）と内部リンクを見直し、次ページの追加を止めて既存ページを改善する |
| 半年 | 2027-05-15 | 月間PV（全体・Organic）、主要KWの順位、PVの推移 | 月間PVが増加傾向で、§1.1 の水準に届く見込みがある | 撤退：新規ページの追加を止め、既存ページは保守のみにする |

判定日の管理は本表を正本とする（未来日付の Issue は起票しない運用のため）。判定日に到達したら判定用 Issue を起票し、§6.2 の形式で実測値と判定結果を記録する。

### 6.2. 計測ルール

- PV・順位は Search Console と GA4 の実測値だけで更新する。推測値を実績として書かない。
- 取得できなかった指標は「取得不可」と書き、理由（権限不足など）を添える。
- 判定時は、本書 §2.2 と同じ形式の表を判定Issueに記録する。

### 6.3. 計測手順

```bash
# GA4：ページ別 PV・セッション（期間は YYYY-MM-DD / NdaysAgo / today）
python3 scripts/ga4_report.py pages --start 28daysAgo --end today
# GA4：流入チャネル別（Organic Search の確認）
python3 scripts/ga4_report.py channels --start 28daysAgo --end today
# Search Console：権限状態・URL検査（権限付与後に検索パフォーマンスも取得可能）
python3 scripts/gsc_tool.py status
python3 scripts/gsc_tool.py inspect https://count.it-araiguma.com/genko
```
